# マトリクスからテストを実装する

## 入力を検証する

1. JSONのパスを特定する。指定がなく候補が複数ある場合は、更新日時で選ばずユーザーに確認する。
2. このSkillディレクトリを基準に次を実行する。

```bash
python3 scripts/validate_workbook_json.py --input <json-path>
```

3. `expected` が `要確認` のケースがあれば実装を停止し、対象IDを報告する。

## 実装する

1. JSONだけをテストケース設計の根拠とする。因子・水準を再設計したり、ペアワイズを再計算したりしない。
2. リポジトリの既存コードは、対象型、呼び出し方法、テストフレームワーク、命名、配置、実行コマンドを判断するためにのみ読む。
3. `テストケース` の各行を漏れなくテストへ対応させる。`memo` は診断メッセージには使えるが、合否条件には含めない。
4. 既存テストがある場合はその形式を優先する。生成先を一意に判断できない場合は編集前にユーザーへ確認する。
5. 対象テストを実行する。失敗した場合は、JSONの期待値を都合よく変更せず、実装・環境・設計不整合のどれかを切り分けて報告する。

## 出力制約

- `testcases/` 配下に追加の中間ファイルや互換コピーを作らない。
- 一時ファイルを作成した場合は完了前に削除する。
- テストコードの出力先、対応ケース数、実行コマンド、結果を報告する。
